# SupportAI — Cloudflare + Groq

A GitHub-ready SupportAI prototype migrated from the supplied Google Opal workflow export.

## What is included

- Responsive support-agent dashboard.
- Groq-powered concise customer response drafting.
- Exact order lookup against Cloudflare D1 (not guessed by the model).
- Five sample orders matching the Opal export.
- Conversation history stored in D1 and reused for follow-up messages within a conversation.
- Ticket records and human-review flags.
- No WhatsApp sending is claimed or implemented yet.

## Important scope

This is a working prototype foundation, not a production-ready commerce integration. The five orders are demonstration data. Before serving real customers, connect an authenticated order source, add customer identity verification, protect agent actions, add rate limiting and logging, and implement the WhatsApp Cloud API webhook/send flow.

The original Opal export contained an AI-generated dashboard step and prompts, but no connected live order database. This project replaces the inferred order lookup with exact D1 lookup. The dashboard is rendered locally rather than regenerated by AI on every message.

## Requirements

- Node.js 20+
- Cloudflare account
- Groq API key
- Wrangler CLI (installed through npm dependencies)

## 1. Install

```bash
npm install
```

## 2. Create a Cloudflare D1 database

```bash
npx wrangler d1 create supportai-db
```

Copy the returned `database_id` into `wrangler.toml`, replacing:

```toml
database_id = "REPLACE_WITH_YOUR_D1_DATABASE_ID"
```

## 3. Create the schema and sample orders

For local development:

```bash
npm run db:local
```

For the remote Cloudflare database:

```bash
npm run db:remote
```

## 4. Add Groq API key

For local development, create `.dev.vars` (do not commit it):

```dotenv
GROQ_API_KEY=your_groq_api_key
```

For Cloudflare:

```bash
npx wrangler secret put GROQ_API_KEY
```

Paste your Groq key when prompted. Never put the key in frontend code or GitHub.

## 5. Run locally

```bash
npm run dev
```

The Vite development server serves the UI. To test the Worker API locally, use:

```bash
npx wrangler dev
```

For the full local Worker + D1 experience, run Wrangler dev after creating the local D1 schema. The dashboard calls `/api/analyze`.

## 6. Deploy to Cloudflare Workers

```bash
npm run deploy
```

The Worker serves the built `dist` frontend and the `/api/*` routes.

## API

### `POST /api/analyze`

```json
{
  "message": "Where is my order ORD-1001?",
  "conversationId": "a-stable-conversation-uuid"
}
```

The first request may omit `conversationId`; the API returns one. Keep and reuse it for subsequent messages in the same conversation.

### `GET /api/history?conversationId=...`

Returns the stored message history.

### `GET /api/health`

Health check.

## GitHub safety

Do not commit `.dev.vars`, API tokens, account IDs that should remain private, or production customer data. `.gitignore` excludes local secrets and build output.
